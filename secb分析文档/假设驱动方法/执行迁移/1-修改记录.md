# hypothesis_update设置为内联工具
日志里提到 Swerex 在安装阶段尝试执行 which hypothesis_update，这是因为我们把 hypothesis_update 当成普通命令加入工具列表，SWE-agent
  默认会对所有命令做 which 检查。刚刚我在 ToolHandler 里加了 _inline_command_names，并在 _is_command_available 中跳过这些内联命令的可
  用性检测，因此不会再触发 NonZeroExitCodeError。重新运行实例时，就能顺利进入主循环并使用 hypothesis_update。

  原因：

  SWE-agent 在启动时会把 所有 已注册的工具名字拿去跑 which <command>，目的是确保这些命令在容器里真有可执行文件。我们新增的
  hypothesis_update 是“内联 Function Calling 工具”，它并不会在容器里对应一个二进制或脚本，目标只是让 LLM 返回 JSON 后由代理本地处理。

  如果不告诉框架这一点，安装流程照样去执行 which hypothesis_update，自然找不到，于是抛出 NonZeroExitCodeError。我做的处理是：构造
  ToolHandler 时把所有 inline commands 的名字保存在 _inline_command_names，然后在 _is_command_available 函数里检测时，一旦发现命令在
  这份列表里，就直接 return，即“跳过可执行检查”。这样框架对真正的外部工具仍然会验证（防止缺安装），而对我们这种纯虚拟工具就不会继续跑
  which，也就不会报错。
